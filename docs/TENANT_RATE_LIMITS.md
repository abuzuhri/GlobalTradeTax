# Tenant request limits

Authenticated merchant requests share a fixed-window budget per tenant, including all active keys for that tenant. It covers quotes, landed-cost estimates, compliance, destinations, dataset validation, UK reference and review routes, the merchant Saleor review endpoint, and installed Saleor App review reads. Authentication precedes the budget and request-body parsing. Saleor App review authentication makes a staff identity query before the budget, so that query is not protected by this limit. Unauthorized requests return 401 without allocating a tenant budget. Health, capabilities, public data sources, operator routes and Saleor setup/callback routes are outside this policy.

Defaults are 120 requests per 60 seconds and 10,000 active tenant windows per process. Configure `TenantRateLimit__PermitLimit` (1–10,000), `TenantRateLimit__WindowSeconds` (1–3,600), and `TenantRateLimit__MaxTenants` (1–100,000); malformed or out-of-range values prevent startup. Exhaustion returns HTTP 429, JSON `tenant_rate_limit_exceeded`, and a positive `Retry-After` in seconds. When capacity is full, new tenants are rejected until an existing window expires; expired windows are reclaimed on demand. There is no queue. Fixed windows allow bursts across window boundaries.

Budgets are local to each application process and reset on restart. Multiple instances do not share a budget; distributed enforcement and edge protection require separate deployment controls. PostgreSQL-backed authentication still queries the database before the budget, and anonymous traffic is not protected by this policy. These limits do not establish production authorization, eligibility or legal approval, and do not enable payment or collection.

Microsoft's [ASP.NET Core rate limiting guidance](https://learn.microsoft.com/aspnet/core/performance/rate-limit?view=aspnetcore-8.0) describes partitioning risks, retry metadata and multi-instance limitations. This implementation uses a bounded local registry because authenticated tenants can otherwise create unbounded partition state.
